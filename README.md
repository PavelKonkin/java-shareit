# ВещьНаВремя
Бэкенд сервиса по шерингу вещей. У пользователей есть возможность брать вещи других пользователей на время. Можно оставлять заявки на нужные вещи и искать их по ключевым словам.

## Дальнейшая разработка
### Перед тем как начать разработку, у вас должны быть установлены следующие зависимости:
- Java 11
- Apache Maven
- Docker
### Сборка и запуск приложения
- Для сборки запустите из корня
  ```bash
  mvn package
- Для тестов запустите из корня
  ```bash
  mvn test
- Для запуска запустите из корня
  ```bash
  docker-compose up
- Сервис разделён на 2 микросервиса: gateway и server. Gateway предоставляет REST api к которому обращаются пользователи, а server обрабатывает запросы от gateway и выдает необходимые данные.
Микросервисы запускаются в Docker-контейнерах.

Gateway запускается на порте 8080, server на порте 9090 , база данных на порте 6541. Если они заняты, нужно сначала завершить друие приложения, которые их занимают.
Если освободить порты нельзя, то нужно изменить порты по умолчанию в docker-compose.yml, а также в файлах настроек сервисов application.yml
- После запуска на хосте localhost:8080 будут доступны следующие эндпойнты:
  - GET:
    - /users - получить список всех пользователей
    - /users/{userId} - получить пользователя по его id
    - /items/{itemId} - получить вещь по ее id. В запросе обязателен header X-Sharer-User-Id со значением id пользователя, запрашивающего вещь
    - /items[?from=0&size=10] - получить список вещей пользователя, разместившего их (хозяина вещей). В запросе обязателен header X-Sharer-User-Id со значением id пользователя - хозяина вещей. В параметр from передается индекс вещи с которого надо начинать список. В параметр size передается количество вещей в списке. Оба параметра необязательные
    - /items/search[?text=&from=0&size=10] - найти вещи по тексту в названии или описании. В параметр text передается текст, по которому надо искать вещи.  В параметр from передается индекс вещи с которого надо начинать список. В параметр size передается количество вещей в списке. Все параметры необязательные
    - /requests/{requestId} - получить запрос на вещь по его id. В запросе обязателен header X-Sharer-User-Id со значением id пользователя, получающего запрос
    - /requests - получить список всех собственных запросов на вещи. В запросе обязателен header X-Sharer-User-Id со значением id пользователя, получающего список своих запросов.
    - /requests/all[?from=0&size=10] - получить список всех запросов на вещи. В запросе обязателен header X-Sharer-User-Id со значением id пользователя, получающего список запросов. В параметр from передается индекс вещи с которого надо начинать список. В параметр size передается количество вещей в списке. Оба параметра необязательные
    - /bookings[?state=&from=0&size=10] - получить список собственных бронирований. В запросе обязателен header X-Sharer-User-Id со значением id пользователя, получающего свои бронирования. В параметр state передается необходимый статус бронирований, допустимые значения - WAITING, APPROVED, REJECTED, ALL, CURRENT, PAST, FUTURE.  В параметр from передается индекс бронирования с которого надо начинать список. В параметр size передается количество бронирований в списке. Все параметры необязательные
    - /bookings/{bookingId} - получить бронирование по его id. В запросе обязателен header X-Sharer-User-Id со значением id пользователя, получающего бронирование
    - /bookings/owner[?state=&from=0&size=10] - получить список бронирований для хозяина вещей. В запросе обязателен header X-Sharer-User-Id со значением id пользователя - хозяина бронируемых вещей. В параметр state передается необходимый статус бронирований, допустимые значения - WAITING, APPROVED, REJECTED, ALL, CURRENT, PAST, FUTURE.  В параметр from передается индекс бронирования с которого надо начинать список. В параметр size передается количество бронирований в списке. Все параметры необязательные
  - POST:
    - /users - создать нового пользователя в базе, требуется тело запроса в JSON формате со структурой вида { name:, email:}, где name это имя пользователя (необязательное поле), email - электронная почта (обязательное поле)
    - /items - добавить вещь для шеринга. В запросе обязателен header X-Sharer-User-Id со значением id пользователя, добавляющего вещь. Требуется тело запроса в JSON формате со структурой вида { name:, description:, available:, requestId:}, где name это название вещи (обязательное поле), description - описание вещи (обязательное поле), available - поле типа булево (обязательное, true - вещь доступна, false - вещь занята), requestId - значение id запроса, по которому добавляется вещь (необязательное поле)
    - /items/{itemId}/comment - добавить комментарий к вещи по ее id. В запросе обязателен header X-Sharer-User-Id со значением id пользователя, добавляющего комментарий. Требуется тело запроса в JSON формате со структурой вида { text:}, где text это текст комментария (обязательное поле)
    - /request - создать запрос на вещь. В запросе обязателен header X-Sharer-User-Id со значением id пользователя, создающего запрос. Требуется тело запроса в JSON формате со структурой вида {description:}, где description - описание запроса (обязательное поле)
    - /bookings - создать запрос на бронирование вещи.  В запросе обязателен header X-Sharer-User-Id со значением id пользователя, создающего запрос на бронирование. Требуется тело запроса в JSON формате со структурой вида { itemId:, start:, end:}, где itemId это id вещи (обязательное поле), start - дата начала бронирования вещи (обязательное поле), end - дата окончания бронирования вещи  (обязательное поле)
  - PATCH:
    - /users/{userId} - обновить информацию о пользователе, требуется тело запроса в JSON формате со структурой аналогичной требуемой при создании пользователя, но все поля необязательные
    - /items/{itemId} - обновить информацию о вещи по ее id. В запросе обязателен header X-Sharer-User-Id со значением id пользователя, обновляющего вещь. Требуется тело запроса в JSON формате со структурой вида { name:, description:, available:, requestId:}, где name это название вещи, description - описание вещи, available - поле типа булево (true - вещь доступна, false - вещь занята), requestId - значение id запроса, по которому добавляется вещь. Обязательные поля только те, которые обновляются.
    - /bookings/{bookingId}?approved= - подтвердить или нет бронирование вещи по его id. В запросе обязателен header X-Sharer-User-Id со значением id пользователя, хозяина вещи. В параметр approved передается true если бронирование подтверждается, с любым другим значением кроме пустого бронирование не подтвержается (обязательный параметр). 
  - DELETE:
    - /users/{userId} - удалить пользователя по его id
